# 프롬프트 재설계 실험 전략 V2

## 현재 문제 진단

### 1. "방어적 프롬프트" 증후군
현재 프롬프트들의 공통 패턴:
- `[금지 사항]`, `[출력 규칙]` 등 제약 조건이 프롬프트의 30% 이상
- "~하지 마세요", "~금지" 등 부정적 프레이밍
- 할루시네이션 방지에 과집중 → 실제 유용한 정보 생성 억제

### 2. 목적 불분명
각 모듈이 "왜" 필요한지가 프롬프트에 반영되지 않음:
- Curriculum: 과목 나열 vs **면접에서 물어볼 핵심 개념**
- Professors: 교수 정보 수집 vs **면접관 관심사 파악**
- Trends: 합격 사례 나열 vs **실제 합격자의 전략 추출**

### 3. 형식 과집중
- 테이블, 체크리스트 등 형식에 집착
- 실제 내용의 깊이보다 구조화에 초점

## 재설계 원칙

### 원칙 1: 목적 중심 (Why-First)
각 모듈의 진짜 목적을 한 문장으로 정의하고, 그것만 요청

### 원칙 2: 사용자 관점 (User-Centric)
"편입 준비생이 이걸 보고 뭘 얻어야 하는가?"

### 원칙 3: 최소 제약 (Minimal Constraints)
금지사항 최소화, 긍정적 지시로 전환

### 원칙 4: 자연스러운 응답 (Natural Response)
딱딱한 구조 강제 대신, 자연스러운 흐름 유도

---

## 모듈별 목적 재정의

### Curriculum
**현재**: 교과과정 분석 + 교육 트렌드
**재정의**: "편입 면접에서 교수가 기대하는 전공 기초 지식은 무엇인가?"

### Professors
**현재**: 교수 정보 수집 (이름, 연구실, 논문)
**재정의**: "이 학과 교수들이 관심 가질 만한 연구 주제와 질문은?"

### Trends
**현재**: 합격/불합격 사례 + 면접 팁
**재정의**: "실제 합격자들은 어떻게 준비했고, 무엇이 결정적이었는가?"

### Synthesis
**현재**: 전략 + 예상 질문 생성
**재정의**: "위 정보를 바탕으로, 이 학생이 면접장에서 할 수 있는 최선은?"

## 실험 설계

### 실험 A: Curriculum 재설계
| 버전 | 접근법 | 프롬프트 길이 |
|------|--------|-------------|
| V1 (현재) | 방어적, 구조 강제 | ~800자 |
| V2 (간결) | 목적만 전달 | ~200자 |
| V3 (대화형) | 튜터 역할 부여 | ~300자 |

### 실험 B: Professors 재설계
| 버전 | 접근법 |
|------|--------|
| V1 (현재) | JSON 구조 강제, null 규칙 |
| V2 (자유형) | 자연어 응답, 핵심만 요청 |
| V3 (면접 연결) | "면접 질문으로 연결될 연구 주제" 요청 |

### 실험 C: Trends 재설계
| 버전 | 접근법 |
|------|--------|
| V1 (현재) | 체크리스트, 테이블 강제 |
| V2 (스토리텔링) | 합격자 이야기 형식 |
| V3 (실전 조언) | "선배가 후배에게" 톤 |

## 평가 기준

### 정량적
- 응답 길이
- 구체적 사례 수
- 실행 시간

### 정성적 (핵심)
1. **실용성**: 편입생이 바로 활용할 수 있는가?
2. **구체성**: 뜬구름 잡는 조언 vs 실제 행동 가능한 조언
3. **자연스러움**: 사람이 쓴 것 같은가?
4. **깊이**: 표면적 정보 vs 통찰

---

## 실험 순서

1. Curriculum V2, V3 실험 → 최적 버전 선택
2. Professors V2, V3 실험 → 최적 버전 선택
3. Trends V2, V3 실험 → 최적 버전 선택
4. 최적 조합으로 Synthesis 재설계

## 가설

> "프롬프트가 짧고 목적이 명확할수록,
> Gemini는 더 자연스럽고 유용한 응답을 생성할 것이다."

이유:
- 긴 프롬프트는 모델이 "규칙 따르기"에 집중하게 만듦
- 짧은 프롬프트는 모델의 자체 지식과 추론을 활용하게 함
